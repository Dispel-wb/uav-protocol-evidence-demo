# 全链路智能通信分析系统：差距审计与实现表

## 当前结论

现有 V0.3 是“解调后字节证据分析原型”，已经证明已知协议解析、混合字节流分流、未知重复结构发现和规则复测可以在同一界面闭环运行。它距离“连续链路智能分析”还有数据时间轴、模型训练评测和跨捕获记忆三项关键能力；距离“射频接收、降噪、波形解调”还缺完整的 IQ 样本链路。

不使用一个容易误导的总完成百分比。下面按可验收关卡衡量距离：每个关卡必须有输入、输出、指标和回归样本。

## 总体顺序

### A. 解调后链路智能分析

- [x] A1 已知协议帧同步、校验和字段解析
- [x] A2 已知协议混合字节流分流
- [x] A3 未知重复结构归族、长度与校验假设
- [x] A4 捕获级覆盖率、完整性、协议组成、切换点和建议
- [x] A5 带时间戳的连续捕获与滑动窗口分析
  - [x] 定义 `capture-chunk-v1`：时间戳、来源、字节、丢包标志
  - [x] 跨块保留半帧，计算吞吐率、间隔和丢块计数
  - [x] 检测协议出现和消失
  - [ ] 增加版本漂移和质量突变检测（归入 A7 的模型与阈值评测）
- [x] A6 协议状态机与因果链
  - [x] 从命令、应答、心跳中恢复会话状态
  - [x] 把异常关联到前置条件和后续结果
  - [x] 用人工标注的正常、缺少前置条件和孤立应答轨迹验证
  - [ ] 扩展真实设备轨迹数据集并统计状态转换准确率（归入 A7 评测）
- [ ] A7 数据驱动的协议敏感度模型
  - [ ] 建立公开或授权捕获集，按设备、协议、版本隔离训练与测试
  - [x] 实现可解释基线：字节直方图、哈希二元组和长度特征的质心分类器
  - [x] 加入相似度阈值与类别间隔阈值，低置信度执行开集拒识
  - [ ] 比较逻辑回归、梯度提升和轻量序列模型
  - [ ] 校准置信度并设置开集拒识，不允许强制归类
- [ ] A8 主动调试与增量学习
  - [ ] 根据不确定字段推荐下一项设备操作
  - [ ] 记录操作前后差分，更新字段与状态假设
  - [ ] 新知识进入候选区，经人工确认后才进入正式模型

**A 阶段完成标准：** 对未参与训练的设备与捕获，输出协议候选、置信度、字段/状态证据和拒识结果；测试集必须按设备隔离，并报告准确率、未知召回率、误报率和分析耗时。

### B. 离线 IQ 信号接入与解调

- [ ] B1 统一 IQ 文件入口
  - [ ] 采用 SigMF 数据与元数据格式
  - [ ] 支持 complex float32 与 complex int16
  - [ ] 保存中心频率、采样率、增益、设备和时间信息
- [ ] B2 信号检测与质量估计
  - [ ] 去直流、幅度归一化、功率谱与噪声底估计
  - [ ] 能量检测并切出突发区间
  - [ ] 输出 SNR 估计和检测阈值证据
- [ ] B3 最小降噪链
  - [ ] 频偏粗校正
  - [ ] 通带滤波和自动增益控制
  - [ ] 对比处理前后 SNR、EVM 或误码率
- [ ] B4 单一调制解调闭环
  - [ ] 优先选择一个真实目标链路，不同时铺开全部制式
  - [ ] 完成载波同步、符号定时、判决、位同步和帧同步
  - [ ] 用已知比特样本测 BER，并把字节送入 A 阶段
- [ ] B5 多候选解调与选择
  - [ ] 在少量候选参数上并行尝试
  - [ ] 以同步质量、CRC通过率和协议证据联合选路
  - [ ] 保存失败候选及其指标，避免黑箱选择

**B 阶段完成标准：** 对固定录制的 IQ 数据，处理后能够稳定恢复字节；每次运行结果一致，并提供处理前后指标、参数和中间产物。

### C. 实时射频接收

- [ ] C1 设备无关采样接口
  - [ ] 通过 SoapySDR 枚举设备并读取连续 IQ 流
  - [ ] 暴露中心频率、采样率、带宽和增益
  - [ ] 检测溢出、超时、时间戳跳变并写入报告
- [ ] C2 实时缓冲和回放
  - [ ] 环形缓冲区与背压
  - [ ] 同一数据既可实时处理也可落盘为 SigMF 后复现
  - [ ] 射频线程与分析线程故障隔离
- [ ] C3 在线降噪、解调与协议反馈
  - [ ] 将 B 阶段离线模块原样接入实时流
  - [ ] 用协议 CRC 和状态一致性反馈候选参数
  - [ ] 监测实时延迟、吞吐、丢样和误码

**C 阶段完成标准：** 指定硬件和实验信号源下连续运行，实时字节输出与离线回放结果一致；断开设备、溢出和弱信号均能明确报错并留下证据。

## 为什么按这个顺序

1. A 阶段决定系统最终要从字节中证明什么，也是 B/C 阶段的验收器。
2. 先做离线 IQ，可以固定输入、重复实验，避免硬件、环境和算法问题同时变化。
3. 最后接实时硬件，SoapySDR 只负责设备与流；采样文件采用 SigMF，解调算法保持独立。

## 技术边界

- 未知协议结构推断不等于破解加密，也不能仅凭字节证明字段业务含义。
- 降噪不能恢复已被信道彻底抹去的信息，必须用 BER、EVM 或协议校验率评估。
- “自动识别调制方式”和“自动解调任意协议”不能作为单一功能验收，应限定信号集合、频段、采样率和信噪比。
- 模型训练数据必须来自公开数据或明确授权采集，训练集与测试集按设备隔离。

## 已选接口依据

- [SoapySDR](https://github.com/pothosware/SoapySDR)：设备枚举、采样参数和连续流接口。
- [SigMF](https://sigmf.org/)：IQ 样本及采样率、中心频率等元数据的可复现存储。
- [GNU Radio Symbol Sync](https://wiki.gnuradio.org/index.php/Symbol_Sync)：载波恢复、符号同步、滤波和解调模块的验证环境。
- Web Demo：继续承担字节层证据展示；RF/DSP 运行在本地后端，通过稳定报告格式连接。
