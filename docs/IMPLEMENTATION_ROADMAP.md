# 全链路智能通信分析系统：差距审计与实现表

## 当前结论

现有版本已从“解调后字节证据分析原型”推进到可复现的有限窗口全链路：既能分析已知与未知协议字节，也能从 SigMF IQ 输入完成信号检测、2-FSK 解调、候选参数选择和 MAVLink CRC 反馈。当前主要差距已经转为真实设备数据、更多调制方式、持续流式处理和跨设备泛化验证。

不使用一个容易误导的总完成百分比。下面按可验收关卡衡量距离：每个关卡必须有输入、输出、指标和回归样本。

**B 阶段完成标准：** 对固定录制的 IQ 数据，处理后能够稳定恢复字节；每次运行结果一致，并提供处理前后指标、参数和中间产物。

**当前合成边界：** 在同一2-FSK生成模型下，噪声标准差0.02～0.12、载波频偏−4 kHz～+4 kHz的20组样本均精确恢复且通过MAVLink CRC；噪声标准差0.18的5组均在突发检测阶段被拒绝，没有产生CRC有效的错误帧。该扫描用于回归和暴露失败边界，不代表真实射频环境性能。

**当前调制形状证据：** 2-FSK与BT=0.5 GFSK各20例、覆盖4档噪声和5档频偏；40例均恢复CRC有效帧。较高SNR的30例调制标签正确，最低SNR的10例全部拒识，错误标签为0。阈值只在确定性合成分布内验证，真实发射机、不同BT和信道失真仍待测试。

**当前BPSK证据：** 4档噪声、5档载波频偏共20例，覆盖噪声标准差0.02～0.12和频偏−500～+500 Hz，20例全部精确恢复。统一候选器未把BPSK误选为FSK，也没有错误载荷通过协议CRC。矩形脉冲、RRC成形和恒定采样钟偏已有独立合成测试，真实采样器和多径仍待覆盖。

**当前QPSK证据：** 4档噪声、5档载波频偏共20例，覆盖噪声标准差0.02～0.12和频偏−400～+400 Hz，20例全部精确恢复。三族候选同时运行时没有误选为FSK或BPSK，也没有错误载荷通过CRC。Gardner定时环已覆盖合成的帧内线性漂移，后续需增加载波环并在真实采样器上校准。

**当前RRC成形证据：** BPSK和QPSK均使用滚降系数0.35的根升余弦发射成形，覆盖噪声标准差0.02、0.04、0.08与频偏−300、0、+300 Hz，共18例。统一候选器18例均选择正确调制与符号率、恢复正确载荷并通过MAVLink CRC；错误调制选择和错误CRC接收均为0。接收端同时尝试积分判决和RRC匹配滤波，由同步字误差、判决置信度与协议证据选路。该测试的发射端和接收端共享实现，真实采样钟偏、多径和发射机滤波偏差仍待验证。

**当前采样时钟偏移证据：** 对RRC成形BPSK/QPSK注入−10000、−5000、0、+5000、+10000 ppm恒定偏移，共10例。固定符号周期精确恢复6例；启用离散漂移候选后精确恢复10例，改善4例且回退0例，错误调制选择和错误CRC接收均为0。另以4个连续MAVLink帧构成长QPSK突发，让偏移由−10000 ppm线性变化至+10000 ppm；离散网格完整恢复0/8例，Gardner环完整恢复8/8例，每例4个协议帧均通过CRC。大偏移用于在有限帧长中显现累积误差，真实晶振抖动与环路参数仍待硬件校准。

**当前多径均衡证据：** 对RRC QPSK加入静态双径，回波延迟覆盖15～50个采样，复增益幅度覆盖0.5～0.8，并在噪声标准差0.03和0.05下形成10例。未经均衡的链路完整恢复0例；使用同步序列训练7抽头复数FIR、再由CRC选路后完整恢复10例，改善10例、回退0例，错误CRC接收为0。该结果只覆盖静态双径和已知同步序列，时变衰落、更多路径、盲均衡及真实信道仍待验证。

**当前脉冲干扰消融：** 对2-FSK、GFSK、BPSK、QPSK各5组注入1%稀疏高幅脉冲。未处理链恢复12/20组，启用稳健阈值和复数插值后恢复20/20组，改善8组、回退0组。该结果只覆盖稀疏脉冲；ADC削顶和同频碰撞仍待单独处理。

**当前窄带干扰消融：** 在7、9、11 kHz三个干扰频点和四种波形组成的12组案例中，未抵消链恢复5组，启用边缘相干音估计与全窗抵消后恢复12组，改善7组、回退0组；12组干净信号均未错误启用抵消。该方法要求音调在窗口首尾持续存在，不能处理只与目标突发重叠的同频碰撞。

**当前硬件阻塞证据：** `reports/hardware_readiness.json` 显示本机尚未安装SoapySDR Python绑定，设备枚举数为0，因此不能声称完成真实接收验证。需要先确定具体SDR型号，再安装匹配的SoapySDR模块和厂商驱动，重新枚举后采集第一份带硬件元数据的SigMF录制。

**当前流式回放证据：** 使用731样本的不整齐分块和容量为2的有界队列，连续处理3份合成录制，3个分析窗口均选择1200 Bd并恢复CRC有效帧；报告保存采集异常计数、队列背压次数和决策延迟分位数。重复窗口不会重复推进协议状态。另有故障源测试验证设备断开会停止采样线程并向上报告，不会静默挂起；主动停止测试验证未达到预设时长时仍能关闭采样并保留停止前的有效协议证据。完整的射频状态轨迹把未解锁心跳、解锁命令/应答、已解锁心跳和起飞命令/应答编码为6个2-FSK IQ窗口；6个窗口全部通过解调与CRC验证，形成2组命令—应答关系并到达 `takeoff-accepted`。异常测试另行覆盖缺少前置条件和缺少应答。

## 为什么按这个顺序

1. A 阶段决定系统最终要从字节中证明什么，也是 B/C 阶段的验收器。
2. 先做离线 IQ，可以固定输入、重复实验，避免硬件、环境和算法问题同时变化。
3. 最后接实时硬件，SoapySDR 只负责设备与流；采样文件采用 SigMF，解调算法保持独立。

## 技术边界

- 未知协议结构推断不等于破解加密，也不能仅凭字节证明字段业务含义。
- 降噪不能恢复已被信道彻底抹去的信息，必须用 BER、EVM 或协议校验率评估。
- “自动识别调制方式”和“自动解调任意协议”不能作为单一功能验收，应限定信号集合、频段、采样率和信噪比。
- 模型训练数据必须来自公开数据或明确授权采集，训练集与测试集按设备隔离。

## 已选接口依据

- [SoapySDR](https://github.com/pothosware/SoapySDR)：设备枚举、采样参数和连续流接口。
- [SigMF](https://sigmf.org/)：IQ 样本及采样率、中心频率等元数据的可复现存储。
- [GNU Radio Symbol Sync](https://wiki.gnuradio.org/index.php/Symbol_Sync)：载波恢复、符号同步、滤波和解调模块的验证环境。
- Web Demo：继续承担字节层证据展示；RF/DSP 运行在本地后端，通过稳定报告格式连接。

## 协议推断方法依据

- [Discoverer](https://www.usenix.org/conference/16th-usenix-security-symposium/presentation/discoverer-automatic-protocol-reverse-enginee)：从消息轨迹进行保守聚类和格式推断，强调不要把不同格式错误合并。
- [NetPlier](https://www.ndss-symposium.org/ndss-paper/netplier-probabilistic-network-protocol-reverse-engineering-from-message-traces/)：通过多序列对齐和概率推断识别消息类型字段，并进一步恢复状态关系。
- [DynPRE](https://www.ndss-symposium.org/ndss-paper/dynpre-protocol-reverse-engineering-via-dynamic-inference/)：通过交互产生额外流量和语义证据，支持本项目的受控操作与主动调试方向。
